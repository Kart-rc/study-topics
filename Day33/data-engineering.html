Understand the idea · 4 min

A building badge should open one finance room, not arrive with a copy of the master key. Data platforms need the same design for S3.

The platform keeps a named trust object. That object can assume an AWS IAM role. A second object narrows the usable bucket path. Users receive permission on the platform object instead of receiving long-lived AWS access keys.

A worked example

The finance pipeline needs s3://company-data/finance/incoming/. The AWS role can read that prefix. The platform object points to the role, and the external-location or stage object points to that exact prefix. A request for hr/payroll/ must fail even if someone guesses its path.

Use case: when to use this

Part of the 4-minute explanation.

When it fits. Use a governed storage trust when jobs or SQL users need cloud files without embedding cloud access keys in notebooks, stages, or connection strings.

Practical example. A finance ingestion job reads one S3 prefix in both Databricks and Snowflake while AWS role trust and platform grants stay centrally managed.

How to decide. Use a separate role and narrow path for a distinct blast radius. Reuse only when ownership, data sensitivity, lifecycle, and audit expectations match. Managed platform storage is simpler when external ownership is unnecessary.

9 minutes · product implementation

Databricks: storage credential → external location

Mechanism. A Unity Catalog storage credential represents the AWS IAM role. An external location joins that credential to an S3 URL. Users receive external-location privileges; they do not receive the AWS key.

# sourced CLI pattern; not executeddatabricks storage-credentials create --json '{"name":"finance_cred","aws_iam_role": {"role_arn":"arn:aws:iam::111122223333:role/finance-read"}}'-- sourced SQL pattern; not executedCREATE EXTERNAL LOCATION finance_incomingURL 's3://company-data/finance/incoming/'WITH (CREDENTIAL finance_cred);

Failure/fix. A valid role with a missing self/trust relationship still fails validation. Configure the AWS trust relationship, validate the credential, then grant only the external-location privilege needed.

Prerequisites and limit. Unity Catalog plus metastore privileges are required. Workspace binding, KMS, network, file-event, and IAM details can add gates. CLI/SQL above did not run.

9 minutes · product implementation

Snowflake: storage integration → external stage

Mechanism. A storage integration stores Snowflake's generated cloud identity, the AWS role ARN, and allowed or blocked locations. An external stage references that integration and must use an aligned URL.

-- sourced pattern; not executedCREATE STORAGE INTEGRATION finance_int TYPE = EXTERNAL_STAGE STORAGE_PROVIDER = 'S3' STORAGE_AWS_ROLE_ARN =   'arn:aws:iam::111122223333:role/finance-read' ENABLED = TRUE STORAGE_ALLOWED_LOCATIONS =   ('s3://company-data/finance/incoming/');CREATE STAGE finance_stage URL='s3://company-data/finance/incoming/' STORAGE_INTEGRATION=finance_int;

Failure/fix. Recreating an integration can change its external ID and break the AWS trust policy. Prefer deliberate alteration; if recreated, update and verify the trust relationship.

Prerequisites and limit. Account privileges and AWS IAM administration are required. Cross-region/provider transfer can cost extra, and government/China regions have restrictions. SQL above did not run.
