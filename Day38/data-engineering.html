Understand the idea · 4 min

A shop can check the mailbox every minute, even when it is empty. Or the carrier can ring a bell when mail arrives.

Polling is the repeated mailbox check. An event-driven trigger is the bell. The bell starts work, but it does not remember which files or rows were safely processed. Durable ingestion state still belongs in Auto Loader checkpoints, a Snowflake Stream, or another explicit progress record.

A worked example

Partner acme sends three order files at 09:00:00, 09:00:20, and 09:01:30. A 60-second quiet window groups the first two files into one run at 09:01:20. The third file starts another run at 09:02:30. The trigger decides when to wake; the ingestion state decides what remains.

Use case: when to use this

Part of the 4-minute explanation.

When it fits. Use change-driven orchestration when arrivals are irregular and frequent polling wastes compute or adds avoidable latency.

Practical example. Wake a bronze-to-silver order pipeline when partner files or table changes appear instead of running an empty job every five minutes.

How to decide. Use a schedule when arrivals are predictable or the source cannot emit a trustworthy signal. Even with triggers, keep processing idempotent and store progress independently because notifications can be delayed, coalesced, or repeated.

9 minutes · product implementation

Databricks: a file-arrival trigger wakes the job; Auto Loader remembers the files

Different jobs for different responsibilities. A Lakeflow Jobs file-arrival trigger monitors a Unity Catalog external location or volume. A quiet window can debounce a burst; a minimum interval caps run frequency. The triggered job can use Auto Loader with a checkpoint to discover and record files durably.

# sourced PySpark sketch; not executed here(spark.readStream.format("cloudFiles") .option("cloudFiles.format", "json") .load("/Volumes/ops/in/orders") .writeStream.option("checkpointLocation", checkpoint) .trigger(availableNow=True).toTable("ops.bronze.orders"))

Failure/fix. Overwriting an existing file with the same name does not trigger a file-arrival run. Prefer immutable file names and let Auto Loader track ingestion. High unrelated change volume above a monitored subpath can also hurt trigger evaluation; scope the external location or volume.

9 minutes · product implementation

Snowflake: a Stream exposes change; a triggered Task consumes it

The trigger watches a Stream, not a storage path. A triggered Task uses WHEN SYSTEM$STREAM_HAS_DATA(...) without a schedule. It starts suspended, so resume it. Snowflake runs one instance at a time and checks again after completion when more Stream data exists.

-- sourced SQL sketch; not executed hereCREATE TASK load_orders  TARGET_COMPLETION_INTERVAL = '15 MINUTES'  WHEN SYSTEM$STREAM_HAS_DATA('orders_delta')AS MERGE INTO silver.orders USING orders_delta ...;ALTER TASK load_orders RESUME;

Failure/fix. The task body must consume changes before the Stream becomes stale. A directory table also needs automatic or manual refresh before a triggered task can detect file changes. Monitor Stream age and task history; do not treat SYSTEM$STREAM_HAS_DATA as a row-count guarantee.
