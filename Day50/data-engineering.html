Understand the idea · 4 min

A restaurant does not call dinner successful because the ingredients arrived. The order must pass receiving, preparation, assembly, privacy, and delivery.

Our synthetic order pipeline has the same chain: a secretless EKS workload authenticates; malformed rows remain inspectable; valid orders expand into item rows; a small product lookup enriches them; customer email is masked for analysts. Every gate must preserve evidence for the next one.

A worked example

File orders-50.json contains order o-50 with two items and one malformed record. The pipeline should publish two enriched item rows, retain one error record, and show ***@example.com to the analyst. A valid identity without table grants must still stop before ingestion.

Use case: when to use this

Part of the 4-minute explanation.

When it fits. Use an end-to-end consolidation case when individual features work but you need evidence that their boundaries compose safely.

Practical example. An EKS order service loads semi-structured files, preserves errors, explodes items, enriches from a 12 MB product table, and publishes an analyst-safe view.

How to decide. Run the smallest representative case that crosses identity, data quality, transformation, performance, and governance. A unit demo is simpler when only one boundary changed.

9 minutes · product implementation

Databricks: secretless Auto Loader to a masked Unity Catalog view

Recall: identity proves the service principal; Unity Catalog grants authorize it. Auto Loader rescues unexpected fields. posexplode_outer keeps item position and empty parents. A broadcast hint is a request whose plan must be inspected. A column mask runs at query time.

-- SQL-first sketch; not executed in DatabricksSELECT order_id, pos, item.sku, item.qtyFROM bronze_orders LATERAL VIEW posexplode_outer(items) p AS pos,item;SELECT /*+ BROADCAST(p) */ o.*, p.name FROM order_items o JOIN products p USING (sku);ALTER TABLE order_fact ALTER COLUMN email SET MASK email_mask;

Execution label. SQL, Auto Loader, federation, and plan inspection were not run in Databricks. The browser is a local teaching model.

9 minutes · product implementation

Snowflake: WIF service user to validated COPY, FLATTEN, managed join, and masking policy

Recall: a WIF TYPE=SERVICE user still needs role, warehouse, and object privileges. VALIDATION_MODE checks instead of loading and cannot be combined with load transformations. FLATTEN emits array indexes. Snowflake chooses the join plan; there is no Databricks broadcast-hint equivalent. A masking policy transforms the column at query time.

-- SQL-first sketch; not executed in SnowflakeCOPY INTO raw_orders FROM @orders VALIDATION_MODE='RETURN_ALL_ERRORS';SELECT r.order_id, f.index AS pos, f.value:sku::string AS skuFROM raw_orders r, LATERAL FLATTEN(input=>r.payload:items, outer=>true) f;ALTER TABLE order_fact MODIFY COLUMN email SET MASKING POLICY email_mask;

Execution label. SQL, WIF, COPY, Query Profile, and masking were not run in Snowflake.
