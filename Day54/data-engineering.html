Understand the idea · 4 min

A library can revoke your card and stop future borrowing. It cannot make the notes you already wrote disappear.

Governed sharing works the same way. The provider exposes a read-only object without first sending a second managed copy. The recipient queries the provider-controlled data through a share. Revoking the grant stops future reads through that path. It does not erase data the recipient was legitimately allowed to export or copy earlier.

A worked example

The provider shares order o54 with status review. Auditor A sees the live value. A also writes a local snapshot. The provider changes the source to approved; the live share now shows approved, while the snapshot still says review. Revocation closes the live path, not the snapshot.

Use case: when to use this

Part of the 4-minute explanation.

When it fits. Use governed sharing when another organization or account needs current, read-only access without a scheduled export pipeline.

Practical example. A regulated data platform exposes a filtered orders view to an external auditor and must be able to revoke future access quickly.

How to decide. Share the minimum object or filtered view, bind access to a named recipient, monitor use, and agree contractually on downstream retention. Use a copied export only when isolation, offline processing, or a fixed historical handoff is the actual requirement.

9 minutes · product implementation

Databricks: OpenSharing grants read-only access to named recipients

First-minute product recall: Day18 separated provider and consumer responsibilities. Retrieve who owns the live object and who owns a downstream copy.

-- Databricks SQL; not executed in productCREATE SHARE audit_share;ALTER SHARE audit_share ADD TABLE main.curated.orders;GRANT SELECT ON SHARE audit_share TO RECIPIENT auditor_a;

The share is a Unity Catalog securable. Recipients read shared assets as read-only. A provider can add or remove assets and grant or revoke recipient access. Databricks-to-Databricks, bearer-token, and OIDC-federated paths have different prerequisites and identity risks. Sharing a filtered view or partition can narrow exposure.

9 minutes · product implementation

Snowflake: an imported database is a read-only view through the share

First-minute product recall: Day18 separated provider and consumer responsibilities. Keep that ownership split while reading the SQL.

-- Snowflake SQL; not executed in productCREATE SHARE audit_s;GRANT USAGE ON DATABASE finance TO SHARE audit_s;GRANT SELECT ON TABLE finance.curated.orders TO SHARE audit_s;-- consumer: CREATE DATABASE audit_db FROM SHARE provider.audit_s;

Secure Data Sharing does not copy the shared data into the consumer account. The consumer creates a read-only imported database and pays compute to query it. Removing an object, account, or share invalidates the shared path immediately. A table the consumer materialized separately is still a copy.
