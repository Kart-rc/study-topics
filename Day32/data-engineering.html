Understand the idea · 4 min

A hotel clerk may open the same booking system as a regional manager, but should see fewer rooms. The table does not change; the visible result changes with the caller.

A row policy is a predicate evaluated at query time. It does not grant table access by itself. First the caller needs ordinary object privileges; then the policy removes rows that are outside that caller's allowed region.

A worked example

The table contains orders east-42, west-77, and east-99. The group east_analysts receives two east rows. west_analysts receives one west row. A governance administrator may receive all three. The physical rows are unchanged.

Use case: when to use this

Part of the 4-minute explanation.

When it fits. Use row-level policy when many users query the same governed table but each user or role may see only a subset of rows.

Practical example. Regional finance teams share one orders table; east analysts must never receive west customer records.

How to decide. Choose a centralized policy when the rule repeats across many tables; use a table-level rule for narrow table-specific logic. Prefer separate datasets when legal or operational isolation requires a stronger physical boundary.

9 minutes · product implementation

Databricks: Unity Catalog row filter UDF

Mechanism. A SQL UDF returns true for rows the caller may see. Attach it with ALTER TABLE ... SET ROW FILTER. Databricks recommends ABAC policies when the same rule must scale across many tagged tables.

-- sourced pattern; not executed hereCREATE FUNCTION governance.region_filter(region STRING)RETURN is_account_group_member('governance_admin')   OR is_account_group_member(concat(region, '_analysts'));ALTER TABLE sales.ordersSET ROW FILTER governance.region_filter ON (region);

Failure/fix. A per-table filter can be missed on a newly created table. For broad repeatable governance, use tagged ABAC policies and test policy coverage. The filter is an added restriction; base privileges are still required.

Boundary. Unity Catalog is required. UDF complexity and secure evaluation can affect optimization. This lesson does not run the SQL.

9 minutes · product implementation

Snowflake: schema-level row access policy

Mechanism. A row access policy is a schema object whose boolean expression is evaluated at query time. Attach it to one or more tables or views. Snowflake evaluates its expression using the policy owner's role, enabling protected mapping-table lookups.

-- sourced pattern; not executed hereCREATE ROW ACCESS POLICY governance.region_policyAS (region STRING) RETURNS BOOLEAN ->  CURRENT_ROLE() = 'GOVERNANCE_ADMIN'  OR EXISTS (SELECT 1 FROM governance.role_region             WHERE role_name = CURRENT_ROLE()               AND allowed_region = region);ALTER TABLE sales.orders ADD ROW ACCESS POLICY  governance.region_policy ON (region);

Failure/fix. A row access policy controls visibility; it does not stop inserts or changes to rows a role can already modify. Grant DML separately and test that policy context, ownership, and mapping rows are correct.

Boundary. Row access policies are an Enterprise Edition feature. Policy evaluation and mapping-table design have privilege and performance implications. This lesson does not run the SQL.
